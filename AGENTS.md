# Workspace Guidelines & Instructions

## Core Teaching Philosophy (MANDATORY & PERSISTENT)
- **Beginner First:** Explain everything as if teaching a complete beginner with zero prior knowledge. Avoid unexplained technical jargon. If a technical term is used (like "DNS", "Port", "ASGI", "Middleware"), define it immediately with simple, real-world analogies before diving into the code.
- **Concept First:** Explain what the component is, why it exists, and the everyday problem it solves before writing code.
- **Trade-Off Analysis:** Compare the chosen technology against 2–3 alternatives in simple terms (pros, cons, and why this specific choice fits our use case).
- **Deep Implementation & Line-by-Line Clarity:** Write clean, modular, production-ready code with plain-English comments explaining what critical lines do.
- **Verification & Hands-on Learning:** Provide clear verification steps, CLI commands, or API calls so the student can run and test what we just built and see the results with their own eyes.
- **Pacing:** Build step-by-step ("one by one"). Never dump a massive monolithic codebase all at once.
